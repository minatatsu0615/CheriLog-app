## 1. サービス概要
- このサービスはどんなサービスか
映画、音楽、旅行、カフェなど、日常のさまざまな「好き」や体験を一つの場所に記録し、カテゴリーごとに整理・振り返ることができるサービスです。
SNSのように人に見せることだけを目的とせず、自分自身の思い出や「好き」を残しておくことを中心としています。
記録が蓄積されることで、過去の体験を振り返ったり、自分の興味や好きなものの変化に気づいたりできるサービスを目指します。
- 誰の、どんな課題を、どう解決するか
対象ユーザー：映画、音楽、旅行、カフェなど複数の趣味や体験を持ち、日常的にSNSやスマートフォンを利用している20代後半〜30代前半のユーザー。
課題：体験するジャンルごとに記録するサービスが分かれていたり、SNSではさまざまな投稿が混在したりすることで、自分の「好き」や過去の体験を一つの場所で整理・振り返ることが難しい。
その結果、記録すること自体を面倒に感じて後回しにしてしまい、せっかくの思い出や、自分が何を好きだったのかを振り返る機会が失われてしまう。
解決方法：映画、音楽、旅行、カフェなどジャンルを問わず、さまざまな体験を一つの場所に気軽に記録できるようにします。さらに、カテゴリーごとの整理や絞り込みによって、過去の体験を簡単に振り返れるようにします。
これにより、「記録する → 整理する → 振り返る」という体験を通じて、自分の「好き」や思い出を残し、過去の体験をもう一度楽しんだり、自分自身の興味や変化に気づいたりできるようにします。

## 2. このアイデアはどこから生まれたか
### 2-1. きっかけとなった体験・感情
私は映画を見たり、音楽を聴いたり、旅行に出かけたり、カフェを巡ったりすることが好きで、その時の思い出を写真やSNSに残すことがあります。
しかし、既存のサービスでは映画は映画、旅行は旅行、カフェはカフェというように、ジャンルごとに記録する場所が分かれていることが多く、不便に感じていました。
一方で、InstagramのようなSNSにまとめて記録する方法もありますが、後から映画だけ、旅行だけといった形で整理して振り返ることが難しくなります。アカウントを複数作成して記録する場所を変えることもできますが、身近な人と共有&知ってもらいたいという気持ちもあるため、それぞれのアカウントで投稿するのも「少し違うかも・・・」と思うこともありました。
その結果、記録そのものを後回しにしてしまうことが増え、時間が経ってから「あのときどこに行ったっけ？」「最近どんな映画を見たっけ？」と思い返しても、せっかくの体験を十分に振り返れないことがありました。
### 2-2. なぜそれが「気になった」のか
自分にとって、映画や音楽、旅行、カフェ巡りなどの体験は、その場で楽しむだけでなく、後から振り返ることで改めて価値を感じられる大切なものです。また、好きなものや体験を記録として残すことは、自分自身の興味や価値観を知るきっかけになり、過去の思い出から前向きな気持ちや活力を得ることにもつながります。さらに、記録を身近な人と共有することで、共通の「好き」を通じたつながりが生まれたり、自分でも気づいていなかった一面を知ってもらえたりする価値もあると考えています。
しかし現在は、体験のジャンルごとに記録する場所や方法が分かれているため、継続的に記録するハードルが高く、結果として大切な思い出や体験が埋もれてしまうことがあります。
こうした課題を感じる中で、「好きなものや体験をジャンルを問わず一つの場所に集約し、後から整理して振り返ったり、人と共有したりできるサービスがあれば良いのではないか」と考え、このアイデアに至りました。

## 4. 想定ユーザーについて
### 4-1. 想定しているユーザー
- 年齢設定
年齢：20代後半〜30代前半
理由：仕事やプライベートが充実し始め、映画、音楽、旅行、カフェ巡りなど、多様な体験をする機会が増える年代である。また、SNSやスマートフォンを日常的に利用しており、体験を写真や投稿として記録する習慣を持つ人が多いため。
- 生活・状況設定
生活・状況：平日は会社員として働き、休日は映画鑑賞や旅行、カフェ巡りを楽しんだりして過ごしている。体験したことを写真やSNSで記録する習慣はあるものの、映画、旅行、カフェ巡りなどの投稿が同じ場所に蓄積され、後から振り返りづらいと感じている。
理由：趣味やライフイベントが増えるほど記録が分散、または混在しやすくなる。その結果、「あの映画いつ見たっけ？」「去年どこへ旅行したっけ？」と振り返りたいときに情報を探す手間が発生する。本サービスによって、ジャンルを横断して体験を整理・蓄積できるようになり、継続的な記録と振り返りを実現できる。
- 環境設定
環境：Instagramや写真アプリ、Filmarksなど複数のサービスを利用しており、家族や友人とSNSで日常的に交流している。
理由：ジャンルごとに別アカウントを作るのは管理や共有の負担が大きい。1つのプロフィール内で体験を整理・共有できれば、手間を減らしながら交流できる。
### 4-2. 自分とユーザーの距離
- 自分自身
→ このアイデアは、自身が映画・音楽・旅行・カフェなどの体験を記録する中で感じた不便さから生まれたものであるため。実際に同じ課題を感じているため、利用シーンや必要な機能を具体的にイメージしやすく、継続的にユーザー視点で改善できると考えている。

## 5. 既存サービス・競合調査
### 5-1. 似たサービスの調査
- サービス名：Instagram
- URL：https://www.instagram.com/
- どんなことができるか
写真や動画を投稿し、フォローしている人の投稿を見たり、いいねやコメントをしたりできます。
24時間だけ残るストーリー機能やノートで友達の近況を素早くチェックすることもできます。
### 5-2. それでも自分が作りたい理由
Instagramはさまざまな体験を手軽に投稿&共有できますが、基本的には新しい投稿が流れていくSNSです。
自分が過去に何をしたのか、どんな映画を見たのか、どんなカフェに行ったのかをカテゴリーごとに整理して振り返ることを目的としたサービスではありません。
また、投稿する内容が「人に見せたいもの」に偏りやすく、「自分のための記録」として気軽に残すには少し違うと感じました。
そこで、SNSとして人とつながることだけではなく、自分自身の体験や好きなものを整理して残すことを中心にしたサービスを作りたいと考えました。
### 5-3. 差別化を「体験価値」で表現する
複数の趣味や体験を一つの場所に気軽に記録し、カテゴリーごとに整理された自分だけの「好き・思い出」をいつでも振り返れる体験。
特に、映画・音楽・旅行・カフェなどを別々に管理するのではなく、一つのアカウントでまとめて管理できることを特徴とします。

## 8. このアプリの懸念点とその対策
- 何が問題になりそうか
カテゴリーが増えすぎると、逆に投稿を整理しづらくなる可能性がある。
- なぜそう思うか
ユーザー自身が自由にカテゴリーを作れるようにすると、似たカテゴリーが複数できたり、カテゴリー数が多くなったりする可能性がある。
- そのために考えている対策
最初は公式カテゴリーを用意し、ユーザー自身が作成できるカテゴリーは必要に応じて追加できる設計にする。

## 9. 今後の展開・発展の方向性
このサービスは、単に体験を記録・投稿するだけではなく、記録が蓄積されることで「自分を知る」「過去を振り返る」「人とつながる」ことができるサービスへの発展を目指す。
### 今考えている発展案
- 機能追加の方向性
• 過去の体験を振り返る機能
　   •「1年前の今日」「過去の旅行」「最近よく行く場所」など、蓄積した記録を自動的に振り返れるようにする。
　   • 年間・月間の体験をまとめることで、自分の1年を振り返ることもできる。
•　自分の「好き」の可視化
　   • 記録した映画、音楽、旅行、カフェなどのデータから、自分がどのようなものを好むのかを可視化する。
　   •「最近は音楽に多く触れている」「以前より旅行が増えた」など、自分自身の興味や行動の変化にも気づけるようにする。
•　おすすめ・発見機能
　  • 自分の過去の記録をもとに、興味のありそうな映画、音楽、場所などを提案する。
　  • 友人や似た嗜好を持つユーザーの記録から、新しい「好き」を発見できる仕組みへ発展させる。
- UI・体験の改善
• 記録するハードルを下げる
    • 写真や位置情報、日時などを活用し、入力項目を減らして短時間で記録できるようにする。
    • 誰かの「いいね！」の数や「記録しなければ」という負担を感じさせず、日常の中で自然に使える体験を目指す。
• 振り返る楽しさを高める
    • 単なる一覧表示ではなく、写真や場所、ジャンル、時系列などから自分の体験を振り返れるようにする。
    • 記録が増えるほど、自分だけのアルバムやライフログができていく感覚を提供する。
- 機能以外の工夫
• 「記録する場所」から「自分の人生を振り返る場所」へ
    • サービスの価値を投稿・記録だけに限定せず、蓄積されたデータからユーザー自身が過去を振り返り、自分の変化や「好き」に気づけるサービスへ発展させる。
• ユーザーが長く使うほど価値が高まる仕組み
    • 「過去の自分から今の自分を知ることができる」ことを、継続利用の大きな価値とし、最終的には、ユーザー自身の記録から新しい映画や旅行先、カフェなどを発見できるサービスへの発展も検討する。

- 今回チャレンジしたい点
    • Railsを使用したWebアプリケーション開発
    • ユーザー、投稿、カテゴリーなどのデータベース設計
    • テーブル同士のリレーション設計

    • テストコードの作成
    • 実際にWeb上へデプロイして公開すること
MVPでは機能を増やしすぎず、「体験を記録する → カテゴリーで整理する → 後から振り返る」というサービスの核となる体験を実現することを重視する。
- 不安な点
RubyやRailsの学習と並行して開発するため、エラーが発生した際に原因を特定するまで時間がかかる可能性がある。特に、Model・Controller・View・Routing・DBの関係を理解しながら実装する必要があるため、機能を一度に増やしすぎないようにします。
### 10-3.キャッチアップ不足の懸念
RailsやRubyの理解が十分でない状態から開発を始めるため、実装途中で理解不足による問題が発生する可能性があります。
特に以下の点を懸念しています。
1. **完成までのハードルが高い**
Ruby、Rails、データベース、HTML/CSS、JavaScriptなど複数の技術を同時に学習する必要があるため、機能を増やしすぎると完成までに時間がかかる可能性があります。
2. **Issueの見積もりが難しい**
現時点ではRailsの理解が十分ではないため、一つの機能を実装するために必要な作業量や、エラー解決にかかる時間を正確に見積もることが難しいです。
そのため、まずはMVPの機能を最小限に絞り、「ユーザー登録 → 投稿 → カテゴリー選択 → 投稿一覧 → カテゴリー絞り込み 」という基本的な体験を完成させることを優先します。
Reactなどのフロントエンド技術については、本リリース後にキャッチアップし、必要性と技術的なメリットを検証した上で導入を判断します。まずはRailsを使ってWebアプリの基本構造を理解し、サービスとして動くものを完成させることを目標とします。
